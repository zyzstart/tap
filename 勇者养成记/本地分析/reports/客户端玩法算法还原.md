# 客户端玩法算法还原：ARM64 指令证据与可执行宿主模型

## 1. 范围、结论等级与限制

本报告不是方法签名清单。已从 ARM64 指令恢复并提供可读算法的范围为：Q32.32 定点数核心运算、MT19937 与随机区间包装、阈值命中、属性加值和合并的关键规则、普通伤害的连续计算流水线、四元素触发伤害、五行汇总、百分比伤害和部分 Buff 伤害。

**没有执行 APK 或其中的 native 代码，没有连接目标游戏服务；所有测试均是宿主 Python 模型测试，不是 native 差分测试。** 未验证 ARMv7、运行时对象布局实际值、所有业务回调、所有特殊伤害类型、或全游戏结果等价。

证据分层：

- **I：指令确认**——读到算术、字段偏移、分支、调用和截断顺序；字段名由元数据定位。
- **M：宿主模型复现**——把已确认子序列转写为 Python，与手算向量/独立宿主参考算法比对；不提升为 native 执行验证。
- **U：未还原边界**——保留虚调用、业务回调、配置来源和特殊分派；不能按名字补全。

主输入为 [ARM64 ELF](<../unpacked/lib/arm64-v8a/libil2cpp.so>)、[dump.cs](<../derived/il2cpp/arm64-v8a/dump.cs>) 和 [script.json](<../derived/il2cpp/arm64-v8a/script.json>)。生成器、输入哈希、版本与范围分别见 [恢复脚本](<../tools/recover_client_algorithms.py>)、[provenance.json](<../derived/client-algorithms/provenance.json>)、[index.json](<../derived/client-algorithms/index.json>)。

本轮归档 **115 个已知入口、1739 条调用/跳转记录、62 项通过的宿主检查**。调用图细分为 1683 条直接调用、43 条范围外直接跳转及 13 条未解析间接调用；这些不是 115 个完整恢复算法的计数。入口数不等于算法覆盖率。归档按“下一个已知可执行入口/段末/64 KiB”确定保守上界；不是精确函数大小，可能包含相邻 stub、遗漏远处基本块。记录也不是完整控制流图：间接 `blr/br` 不自动解析。

## 3. FP：不是浮点，也不是统一“向零取整”

### 3.1 表示和基础运算（I/M）

`BattleCore.FP` 为有符号 64 位 Q32.32；以下 `raw` 为底层整数，`ONE=4294967296`，`wrap64` 取低 64 位再解释为有符号数。

```text
FP.int(n) = wrap64(int32(n) << 32)
Add(a,b) = wrap64(a+b)
Sub(a,b) = wrap64(a-b)
Mul(a,b) = wrap64((signed64(a)*signed64(b)) ASR 32)
AsInt(a) = int32(a ASR 32)
Q(a) = FP.int(AsInt(a))
```

乘法不是用 Python/浮点四舍五入。`0x1ed4084..0x1ed40a0` 的分肢乘积等价于上式：

```text
y*(x ASR 32) + (y ASR 32)*(x & 0xffffffff)
+ (((y & 0xffffffff)*(x & 0xffffffff)) LSR 32)
```

负数小数向下取整：`Mul(raw=-1, ONE/2)=-1`；`AsInt(-0.5)=-1`。加减和乘积保留 64 位回绕，不是饱和。

`Round` 在 `0x1ed3fbc..0x1ed3ff8` 使用半值与整数位奇偶，**最近值、正好一半取偶数**：`±0.5→0`、`±1.5→±2`。最大正 raw 的 Round 会回绕到最小负 raw。它与 Div 的舍入规则不同。

显式转 long 的 `0x1ed4a34` 与 AsInt 主体 `0x1ed5360` 都能看到高 32 位提取，但当显式 long 结果随后交给 implicit-int 重载，调用者只取低 32 位。伤害流程中的 `Q` 必须保留这个窄化点，不能把全流程都留在无限精度 FP 中。

### 3.2 除法和特殊值（I/M，穷尽边界未验证）

`Div` 入口 `0x1ed4188`：按无符号幅值进行规范化长除法，初始 bit position 为 33，先剥离分母低零 nibble，循环累加商位，最后 `((qsum+1) mod 2^64) >> 1` 再恢复符号。普通有限数对应“最近值、半值远离零”。

**溢出/除零饱和使用 MaxValue/MinValue，不是正负 Infinity：**

| 静态字段 | raw 十六进制 |
|---|---|
| Precision | `0x1` |
| MaxValue | `0x7ffffffffffffffe` |
| MinValue | `0x8000000000000002` |
| PositiveInfinity | `0x7fffffffffffffff` |
| NegativeInfinity | `0x8000000000000001` |
| NaN | `0x8000000000000000` |

分母为零时：正分子→MaxValue，负分子→MinValue，零分子→0。关键饱和加载位于 `0x1ed4330` 和 `0x1ed4394`。不能把 Python 的异常或 IEEE754 NaN 规则套进来。

模型保留 ARM64 U64 中间回绕；4096 个有限数向量对照独立有理数舍入、4096 个乘法向量对照分肢法与大整数法。没有证明所有 2^128 输入组合。

## 4. TSRandom 与 TestRate（I/M）

### 4.1 引擎为 MT19937

构造 `0x21a548c` 建立 624 个 uint32 状态、`mti=625`、`mag01={0,0x9908b0df}`。`init_genrand 0x21a5550`：

```text
mt[0]=uint32(seed)
mt[i]=uint32(1812433253*(mt[i-1] XOR (mt[i-1]>>30))+i)
mti=624
```

`genrand_int32 0x21a5a24` 的 twist 使用 N=624、M=397、上位掩码 `80000000`、低位掩码 `7fffffff`；第二段更新引用已经更新的状态，末项使用 `mt[396]` 和新 `mt[0]`。指令把低位是否为 1 单独用于 mag01 索引，同时组合其余位；等价于标准 MT 的右移/异或。temper 为 `>>11; <<7 & 9d2c5680; <<15 & efc60000; >>18`。未显式 seed 的 mti=625 路径 seed=5489。

seed5489 前十个 uint32 为：

```text
3499211612 581869302 3890346734 3586334585 545404204
4161255391 3922919429 949333985 2715962298 1323567403
```

测试向 Python 标准库 MT 注入**相同状态数组**，避免不同 seed 展开方式造成伪差异；5 个 seed 各比较 1875 次 draw，跨越三次状态块更新。只证明宿主实现间的一致性，不是与 APK 运行结果比对。

### 4.2 包装函数的端点不能省略

```text
NextFP() = Div(FP.int(genrand_int32() >> 1), FP.int(0x7fffffff))
Next(FP lo, FP hi):
  lo==hi: 直接返回 lo，不抽样
  lo>hi: 有符号交换
  return lo + Mul(NextFP(), (hi-lo)+raw(1))
TestRate(val) = Next(FP.Zero,FP.One) < val
```

`TestRate 0x16a0314` 使用严格小于，并非 `<=`。它即使 val<=0 也先抽样，没有“概率<=0 不消耗 RNG”的短路。FP 的 `+1` 是 **1 个 raw 最小单位**，不是 FP.One。

| uint32 word | NextFP raw | Next(0,1) raw |
|---|---:|---:|
| `00000000` / `00000001` | 0 | 0 |
| `00000002` | 2 | 2 |
| `7ffffffe` | 2147483647 | 2147483647 |
| `fffffffc` | 4294967294 | 4294967294 |
| `fffffffe` / `ffffffff` | 4294967296 | **4294967297** |

因此最大 word 时 `TestRate(ONE)` 和 `TestRate(ONE+raw1)` 都是 false，直到 `ONE+raw2` 才是 true。不能仅按方法名宣称区间 `[0,1)` 或命中率 1 永远成功。

int 重载 `0x21a56f0`：有符号交换 lo/hi，width=int32(hi-lo)，r=word>>1，然后 `int32(r-SDIV(r,width)*width+lo)`。有模偏差；没有相等 guard。ARM64 `SDIV(n,0)=0`，因此 lo=hi 时实际机器算式为 int32(lo+r)，不是“直接返回 lo”。这是机器层行为，不是推荐调用方式。

## 5. 属性叠加与合并（I/M，字段映射未全覆盖）

关键入口：`ActorAttrData.CalAddVal 0x1751758`、`ActorAttrImpactData.CanMerge 0x17535e8`、`Merge 0x1753648`、`ActorAttrImpactMgr.RefreshFinalAttr 0x1753c04`、`CalAttrList 0x1753e30`。

```text
CalAddVal(base, addType, value):
  1 ABSOLUTE_VAL: return base+value
  2 SUM_PERCENT_VAL / 3 MUL_PERCENT_VAL: return base+Mul(base,value)
  其他: return base
CanMerge(a,b): a.addType==b.addType && a.dataType==b.dataType
Merge(current,incoming):
  total=current.value+incoming.value
  if dataType==16 && addType in {2,3} && total<=-ONE:
     不更新 current.value                     # 不是 clamp 到 -ONE
  else: current.value=total
```

类型16在元数据中为 `BattleCore.ActorAttrDataType.AttackSpeed`。Impact 字段偏移为 producer+10、addType+18、dataType+1c、value+20、priority+28。

刷新顺序是 type1 列表 +20 → type2 列表 +28 → type3 列表 +30；每个列表顺序调用 CalImpact。**局部 CalAddVal 中 type2/type3 算式相同，不代表总叠加规则相同**：合并、分组和顺序仍可改变结果。MergeAttrImpact 中 existing.priority>incoming.priority 分支转入插入路径；完整插入稳定性、全部 CalImpact/SetAttr 字段跳表、MaxHP 等整数属性转换尚未逐项还原，不能宣称所有属性已复刻。

## 6. 普通伤害：CalWeaponDamage 外层

主证据：[CalWeaponDamage 反汇编](<../derived/client-algorithms/disassembly/0169c160_A3BattleCore.SkillDamageHelper_CalWeaponDamage.asm>)。

外层清空 DamageInfo，读取 HitInfo.source(+18)/target(+20)，空 actor/不等价为有效 actor 的分支退出。`SkillAttrDamageData` 的 MagicType+10 写入 info.magicType；非零 MagicType 先把输入 ratio 乘以源属性的对应魔法系数。`GetMagicRatio 0x169e2d0` 的表：1毒、2雷、3火、4冰；其他返回 ONE。

SkillAttrDamageType 枚举1..22的主跳表位于 `0x239fd0c`，表项为以表基址为原点的 signed32 相对地址，已全部解码，**解码地址不等于完成各分支算法**。已逐指令确认的常用入口：

| AttrType | 原生目标 | 输入整理 |
|---|---|---|
| 1 DMG_WEAPON、16 ATTACK_IGNORE_SHIELD | `169c510` | 普通 inner；hasDefend=true；ratio*=Param1；additive=Q(Param2) |
| 2 DMG_NO_DEFEND | `169c614` | 普通 inner；hasDefend=false；ratio不乘Param1；additive=Q(Param2) |
| 3 DMG_RATIO | `169c678` | percent inner；hasDefend=false；ratio不乘Param1；additive=Q(Param2) |
| 14 NO_DEFEND_BY_CASTER、17 IGNORE_SHIELD_AND_DEFEND | `169c58c` | 普通 inner；hasDefend=false；ratio*=Param1；additive=Q(Param2) |

**不要因为两个枚举共享此跳表分支，就推断 ignore-shield 在全局一定无差异**；护盾处理还可能发生在调用者/后继业务。11、12、13涉及五行特殊分支，22涉及四元素特殊分支，仍有内部属性选择跳表和合并逻辑未完整解释。

### 很容易漏掉的最终后处理（I/M）

大部分分支返回后汇合至 `0x169c3c4`：

```text
if info.damage >= 1 && target有效 && target.AttrData.HurtAddRatio > 0:
    info.damage = AsInt(Mul(FP.int(info.damage), ONE+target.HurtAddRatio))
```

位置 `0x169c424..0x169c4c8`。它使用 inner 已存储的**整数** damage 再乘，且不重算 isDead。因此不能仅拿 inner 最后一个公式当作公开 CalWeaponDamage 的完整返回结果，也不能按最终整数 damage 倒推 isDead 必然相同。

## 7. DoCalcWeaponDamage：确认的连续流水线

主证据：[普通 inner 反汇编](<../derived/client-algorithms/disassembly/0169e3bc_A3BattleCore.SkillDamageHelper_DoCalcWeaponDamage.asm>)，入口 `0x169e3bc`。以下 `a` 为复制/招式属性刷新后的源属性，`t` 为目标属性；所有 Add/Sub/Mul 都按第3节 raw 与回绕规则，`Q` 明确执行 floor→int32→FP。

### 7.1 前置门控、属性准备和 RNG 顺序（I/U）

1. `CanBeDamaged` false：damage=0 后返回，不在该分支重写 isDead。
2. Context.IsPengPengTuTeng(+ac) 为 true：damage=AsInt(原始源 Damage)，直接返回。
3. 源属性复制到临时对象；用 source 的招式属性 manager 和 HitInfo.id(+10) 刷新临时属性。目标属性单独读取。
4. `TestRate(t.DodgeRatio-a.HitRatio)` 成功：isMiss=true，退出。
5. `worldScalar=ONE`；Context.IsYiJieShouChao(+af) true 时加 `a.DiffWorldAtkAddRatio`。
6. 按 Sky→Terra→Ocean→Chaos 执行四元素 hit 判定；只有 hit 成功才进行该元素的 crit 判定，故不能预抽固定数量随机数。
7. 目标虚谓词槽+238为 true 时不抽 HeadShotRatio；否则 TestRate(a.HeadShotRatio)。判定成功后，源 Context.+af 为 false 或目标另一虚谓词槽+288为 false，进入秒杀分支。两个虚谓词的业务名称尚未确认。
8. 秒杀分支写 isHeadShot/isDead=true，damage=int32(HP+(max(HpCount,1)-1)*MaxHP)，然后返回；四元素虽已可能写入数组，不再执行普通尾部聚合。

### 7.2 四元素（I/M）

每个渠道：

```text
if TestRate(a.ElementHitRatio):
    x=a.ElementAtk
    if TestRate(a.ElementCritAtkRatio):
        x=Mul(x, ONE+native_loaded_crit_multi)
    candidate=Mul(Max(x-t.ElementDef,0), a.ElementAddRatio)
    if candidate>0:
        info.isHaveElemDamage=true
        info.isHaveElemDamageType[index]=true
        info.elemDamage[index]=int32(existing + AsInt(Mul(candidate,worldScalar)))
```

- Sky：index0，crit ratio/multi +2b0/+2b8；Terra：index1，GroundCritAtkRatio/Multi +2c0/+2c8；Ocean：index2，+2d0/+2d8。
- **Chaos：index3，crit判定读 ChaosCritAtkRatio +2e0，但倍率在 `0x169ed34` 实际读 +2d8，即 OceanCritAtkMulti，而不是 +2e8 的 ChaosCritAtkMulti。** 这是该 ARM64 样本的明确 load，保留为观察到的实现异常，未擅自修复；是否设计意图/版本缺陷不作判断。
- AddRatio 直接相乘，**不是** `ONE+AddRatio`。
- 元素暴击后没有先 Q 的截断；普通暴击则有。
- flag 先于 worldScalar 乘法设置；candidate>0 但 worldScalar=0 时仍可能 flag=true、整数贡献0。
- 元素贡献逐个乘 worldScalar 后转整数，最终聚合时不再给元素总和乘 worldScalar。

### 7.3 普通基数、暴击、技能加伤（I/M/U）

```text
d=a.Damage + FP.int(source.BuffMgr.ProcessAtkVal(target))
if 原始源 AttrData.Damage < 0:
    info.isShowZero=true; info.damage=0; return
if TestRate(a.CritAtkRatio + source.BuffMgr.ProcessCritRatio(target)):
    d=Q(Mul(d, ONE+a.CritAtkMulti))
    info.isCrit=true
skillScalar=ONE
if config存在 && config.CostMP != 0 && a.SkillDamageAdd > 0:
    skillScalar=Mul(skillScalar, ONE+a.SkillDamageAdd)
d=Mul(Mul(d,damageRatio),skillScalar)+damageAdditive
```

锚点：基数 `169ef6c..169efe0`；原始负 Damage 门 `169f028..169f048`；暴击 `169f050..169f138`；技能门 `169f16c..169f224`；顺序乘法 `169f24c..169f274`。其中 `169f16c` 明确调用 `A3BattleCore.SkillConfigMgr.GetSkillBaseConfig`，返回类型由 [dump.cs:181329–181350](<../derived/il2cpp/arm64-v8a/dump.cs#L181329-L181350>) 追到 `BattleCore.SkillBaseConfg`，其 +20 是 [CostMP:168410–168420](<../derived/il2cpp/arm64-v8a/dump.cs#L168410-L168420>)，不是按任意同名配置猜测。ProcessAtkVal 返回 int32，ProcessCritRatio 返回 FP；它们内部尚未还原，模型把已处理基数/判定作为输入。

HitInfo.source 的虚槽+198返回1才进入玩家武器加伤路径。类型1/2/3/4分别加 JianDamage/NuDamage/ShanDamage/FeiDaoDamage，表 `0x239fdc8` 已解码。该虚谓词完整名称/派生覆盖尚未解析，不能简单替换成“所有源都加武器伤害”。

### 7.4 减伤、穿透、下限与格挡（I/M）

HitInfo.+28：1取 CollisionDamageReduce/Ratio 与源 CollisionDamageAdd；0取 BulletDamageReduce/Ratio 与源 BulletDamageAdd；其他值在普通 inner 取零。百分比 inner 的非1分支则一律取 bullet，不能混用。

```text
d += selected_source_add
minimum=Mul(d, GetFloatParam(31))
if hasDefend:
    effectiveRatio=Max(target_reduce_ratio-a.HurtThroughRatio,0)
    effectiveFlat=Max(target_flat_reduce-a.HurtThrough,0)
    d=Q(Mul(d, ONE-effectiveRatio))
    d-=effectiveFlat
    d+=Max(a.LevelPressure-t.LevelPressure,0)
d=Max(d,minimum)
if TestRate(t.BlockDamageRatio):
    info.isBlockDamage=true
    d-=Mul(d,t.BlockDamage)
d=Max(d,0)
```

锚点：类型选择 `169f554..169f5d0`；source add `169f5f0..169f608`；参数31与 minimum `169f624..169f644`；穿透/减伤/等级差 `169f680..169f790`；minimum `169f7d0..169f7e0`；block与0下限 `169f7e4..169f894`。

注意 minimum 在减伤前计算，应用于减伤后、格挡前；格挡仍可把最终物理部分打到 minimum 以下。effectiveRatio 只 clamp 下限0，不 clamp上限1；不要加入原生没有的上限。参数31的配置实值未从此函数确定。

### 7.5 五行、最终聚合与死亡判定（I/M/U）

```text
five=0
for e in [Metal, Wood, Fire, Water, Earth]:   # 原生加法顺序
    five += Max(a.Atk_e-t.Def_e,0)
five=Mul(five,fiveEleDamageRatio)
if five>0:
    info.isHaveFiveEleDamage=true
    info.fiveEleDamage=int32(existing+AsInt(five))
d=Mul(d+FP.int(info.fiveEleDamage),worldScalar)
elemTotal=int32(info.elemDamage[0]+...+info.elemDamage[3])
d += FP.int(elemTotal)
fullFinalFP=d
info.damage=AsInt(d)
if source.BuffMgr.ProcessCauseDeath(target,info):
    info.isDead=true
    info.damage=int32(HP+(max(HpCount,1)-1)*MaxHP)
    info.isCauseDeath=true
else:
    info.isDead=(HP>=1 && FP.int(HP)<=fullFinalFP)
```

锚点：五行 `169f8d0..169fa18`；整数累积 `169fa50..169faa0`；world乘法 `169fae0..169fb00`；四元素int32总和 `169fbc8..169fbd0`；最终加法/存整数 `169fbec..169fbfc`；CauseDeath `169fc3c`；覆盖 `169fd00..169fd18`；fullFP致死比较 `169fd20..169fd64`。

**没有在最终聚合后再次 clamp0**；若已有五行整数/元素整数或worldScalar为负，不能假设输出一定非负。五行整数累积和元素整数总和有 int32 回绕。常规 isDead 比较的是 fullFinalFP，不是 info.damage；CauseDeath 回调则可直接覆盖整数。外层 HurtAddRatio 更晚发生，且不会更新已写出的标志。

## 8. 百分比、五行专用与 Buff 子程序

### 8.1 百分比 inner（I/M）

[百分比反汇编](<../derived/client-algorithms/disassembly/0169fdb0_A3BattleCore.SkillDamageHelper_DoCalcWeaponDamageWithPercent.asm>)，`0x169fdb0`：复制/刷新源属性后，核心为：

```text
d=Q(Mul(FP.int(target.MaxHP),damageRatio))+damageAdditive
if hasDefend:
    # hitType==1 collision，否则 bullet
    d=Q(Mul(d,ONE-target_reduce_ratio))-target_flat_reduce
info.damage=AsInt(d)
info.isDead=(HP>=1 && FP.int(HP)<=d)
```

无已观察到的 minimum、block、穿透、五行叠加或0下限。CanBeDamaged=false分支仅写damage0然后退出，不重写isDead。负数结果在宿主测试中刻意保留。

### 8.2 五行专用（I/M）

`DoCalcDamageWithFiveEle 0x16a01c8` 核心使用现有 info.fiveEleDamage，而非在该子程序重新遍历属性：`info.damage=AsInt(Mul(FP.int(info.fiveEleDamage),fiveRatio))`；致死为 HP>=1 && HP<=damage。CanBeDamaged=false 仅写0。普通 inner 的五行预聚合与这个专用子程序不能混为同一算法。

### 8.3 CalcBuffDamage（I，模型仅覆盖非治疗整数输入）

`0x16a064c` 的 impactType4治疗分支：若 RecoveryHpPercent>0，则先加 `FP.int(int32(floor(Mul(v,RecoveryHpPercent))))`，再加 `FP.int(int32(floor(RecoveryHpVal)))`；missing=int32(MaxHP-HP)；结果为 `-Min(v,FP.int(missing))`，最后 AsInt。非治疗分支为 `Max(Mul(v,ONE-BulletDamageReduceRatio)-BulletDamageReduce,0)`，最后 AsInt。

TSMath.Min 在 `0x21a2438` 调用 FP.LessThan 后 csel；Max 在 `0x219f028` 调用 FP.GreaterThan 后 csel，其远处初始化续块 `0x21a8640` 已另存。它们不是额外隐含百分比/限制器。治疗分支尚无独立宿主模型，不把只测过的整数非治疗模型宣传为完整 Buff 行为。

## 9. 独立模型向量及其含义

本轮62项检查包含以下不能由签名列表得出的约束：

- Round 半值取偶数、负半值、raw最大值回绕；AsInt负小数向下取整；乘法负小量与溢出；除零饱和值区分 Infinity。
- RNG最大word得到 NextFP=ONE，但 Next(0,1)=ONE+raw1；阈值严格不等；FP相等区间不抽样；int相等区间的 SDIV0 行为。
- 攻速合并到-ONE被拒绝而非clamp；其他属性无该拒绝门。
- 普通暴击先整数化，元素暴击不提前整数化；元素flags在world乘法前设置；int32数组累积回绕。
- 防御minimum先于block，元素总和先int32再FP，最终聚合无0下限，外层加伤使用已截断整数。

一个手算二进制精确小数向量：基数101，ratio1.5，skillScalar1.25，additive2.5，武器加3.25，命中类型加4.125，得到199.25；minimum比率0.25得到49.8125；有效减伤比率0.125后先floor为174，再减有效flat4.25、加等级差4，得到173.75；block0.25后130.3125；五行整数5，worldScalar1.5，元素整数总和10，得到 **212.96875，存储damage=212**。该向量只验证模型的确认尾部，不含RNG/业务对象/回调。
