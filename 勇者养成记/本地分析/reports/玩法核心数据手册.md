# 玩法核心数据手册

本轮合并目录覆盖 **545 份源表 / 439 个表名**（包含 fp/nonfp 变体）。

- 有对应原生读取布局证据并通过回编码：**444 份，363,190 条记录**。
- 伴生变体约束下恢复的候选布局：**23 份，14,679 条**，不计入上一项。
- 仍未完整恢复：**78 份**，逐表列入[未解清单](<../derived/gameplay-catalog/unresolved.json>)。
- 数量按源表/源记录统计，不能把 fp/nonfp 重复记录当成不同玩法内容。
- 全程离线静态处理；没有运行 APK、调用游戏原生函数或访问游戏服务器。

## 一、直接查数据

[完整目录 JSON](<../derived/gameplay-catalog/catalog.json>) · [表目录 CSV](<../derived/gameplay-catalog/tables.csv>) · [核心实际样例](<../derived/gameplay-catalog/core-examples.json>) · [属性字典](<../derived/gameplay-catalog/attribute-dictionary.json>) · [枚举常量](<../derived/gameplay-catalog/enums.json>)

[查询脚本](<../tools/query_gameplay.py>)默认只检索有原生布局证据的输出；候选变体必须显式加 `--allow-candidate`。字段可以用点号访问嵌套值。

```powershell
python -B 本地分析/tools/query_gameplay.py --list
python -B 本地分析/tools/query_gameplay.py --table ResDef.EquipConfig --where ItemID=11101
python -B 本地分析/tools/query_gameplay.py --table ResDef.SkillBaseConfg --where SkillID=1001
python -B 本地分析/tools/query_gameplay.py --table ResDef.EquipUpLevelConfig --where Type=1 --where Level=1
python -B 本地分析/tools/query_gameplay.py --table ResDef.BootyConfig --where BootyID=9999 --limit 30
```

## 三、已经拿到的具体玩法内容

### 技能

技能主表现在含完整 `AttrDamageData[2]` 和 `BuffID[4]`，不再只剩 SkillID。`SkillID=1001` 的中文表为“剑普攻”，说明“向正前方发射一颗子弹，攻击频率中等”；第一伤害项 `MagicType=0, AttrType=1, Param1=1, Param2=0, Param3=0`。这些是原表值，不代表最终伤害只有一次乘法。

`BattleCore.SkillAttrDamageType` 枚举位于[声明证据](<../derived/il2cpp/arm64-v8a/dump.cs#L168359-L168386>)：`1=ATTR_TYPE_DMG_WEAPON`；其他分支包含无防御伤害、生命/魔法比例、五行、护盾等。原表的 AttrType 是 int，枚举仅提供同名数值导航，运行时分派须看算法证据。

### 装备与成长

装备主表现在含 `ImpactData[4]` 和 `OpenHoleList[6]`。`ItemID=11101`“狼牙长矛”的第一属性项为 `DataType=2, AddType=1, Value=60, LvAddValue=0`；中文描述有“命中后 1.5 秒攻速加成，最多叠加 3 层”。描述文本不是已还原的 Buff 生效代码。

同名属性枚举中 `2=Damage`、加成枚举中 `1=ABSOLUTE_VAL`，来自[属性与加成枚举声明](<../derived/il2cpp/arm64-v8a/dump.cs#L201208-L201319>)。原字段为 short/byte，不能仅因编号相等就对所有扩展系统作同样语义假设。

强化表 `Type=1, Level=0/1/2` 的第一属性 `Value=0/5/10`；对应 `MoneyNum=100/200/400`、`DecomposeMoneyNum=0/100/300`。这里只展示真实三行，**不把有限样例外推为全等级线性公式**；全量 3,306 行可直接查询。

### 掉落

Booty 主表现在恢复 `ItemParam[3]`；样例 `BootyID=9999` 包含多条奖励记录，首项 `ItemType=10, ItemID=9999901, ItemCnt=1, ItemParam=[3,0,0], RandParam=10000, AwardCnt=22`。

[奖励类型枚举](<../derived/il2cpp/arm64-v8a/dump.cs#L202122-L202194>)里 `10=BOOTY_ITEM_TYPE_EQUIP`。这不意味着每个奖励 ItemID 都必然存在于普通装备主表；特殊生成装备/模板必须结合调用路径另查。**RandParam=10000 不能在未还原对应抽样分支时直接称为 100% 掉率**；也不默认同组归一化或独立判定。

## 四、原始数值与候选变体

FP 字段保留 `__raw_int64`；递归扩展输出另有 `__decimal` 十进制字符串镜像，避免 JavaScript/表格软件损失 64 位整数精度。FP 算术的 Q32.32 还原不自动证明任一字段的时间、倍率或百分数单位。

另有 23 份候选变体：把已验证伴生表的 float/FP 宽度、嵌套结构转移后，要求每个已命名叶子值相等或经 float32 位级投影完全一致，并验证 CRC、记录数、EOF、逐字节回编码。无目标变体对应原生 unpack 证据，因此单独列类。额外字节/字符串保留为未命名字段，未赋玩法语义。

[平面变体候选证据](<../derived/config-layout-recovery/layout-index.json>) · [递归变体候选证据](<../derived/config-layout-recovery-recursive/layout-index.json>)
