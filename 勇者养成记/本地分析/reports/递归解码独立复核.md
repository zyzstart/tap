- 真正的重点方法均以 X 寄存器保存 self/buffer，并在 reader 或 nested unpack 调用前恢复相应接收者和目标地址。未在这些原始方法里发现下述变异复现中的截断保存或破坏 buffer 的 store。

## 发现的问题（修复前）

### P2-1：W 寄存器写入未清除符号指针身份

**原问题位置：**修复前 `putreg`（当时 162–168 行）只有整数值在 W 写入时执行 32 位截断；符号 self/buffer 等仍保持原 tuple。当前修复已在 [narrow_w:160–168](<../tools/decode_resbin_extended.py#L160-L168>) 中拒绝这类截断。

**最小异常：**把 ResAttrLvImpactData 的 VA `0x1e8947c` 从 `MOV X19,X1` 改成 `MOV W19,W1`（清除指令字 sf bit31），分析器仍接受完整的四字段布局。真实 ARM64 的 W 写入会清除高 32 位，不能证明 X19 仍是原始 64 位 buffer 指针。该异常说明来源证明门禁存在漏检，而不是原始方法本身使用了错误指令。

**建议：**对指针类符号的 W 写入拒绝，或者明确建模每种符号的位宽与截断；保留受管 array length 等确有依据的 32 位量。加入上述负向回归。

### P2-2：未建模 store 可破坏 reader 接收者而仍宣称成功路径

**原问题位置：**修复前的 store 处理（当时 318–332 行）对任意已知地址写入仅记录到模拟 memory；未知地址可静默跳过。调用 reader 时没有验证这些写入对 opaque reader 的影响。当前修复已在 [store 门禁:373–383](<../tools/decode_resbin_extended.py#L373-L383>) 限制目的地和 read-result 回写来源/宽度。

**最小异常：**把同一方法 VA `0x1e89498` 的 `MOV X2,XZR` 改成 `STR XZR,[X19,#0x10]`（指令字 `0xf9000a7f`），分析器仍接受相同四字段布局。但 X19 是 PbReadBuf，+0x10 是其底层数组引用；该 store 将它清空。真实 readInt16 会读取该引用、遇 null 返回 -0x16，不能到达宣称的全部成功路径。[readInt16 对应原生证据:17–28](<../derived/config-extended/native/PbReadBuf.readInt16.asm.txt#L17-L28>)。

**建议：**只允许确实支持的安全 stack store，以及有类型/地址/宽度证据的 read-result 回写；拒绝 buffer、未知目的地、其他未建模 self/object 写入。加入该负向回归。

### 两个复现的共用脚本

下面只做主机侧静态分析。修复前两项均显示 `ACCEPTED`；修复后独立复测已确认各自抛出 EvidenceError。`Native.instructions` 的替换只存在于该 Python 进程内。

```python
import sys, copy, struct
sys.path.insert(0, r'D:\VibeCoding\勇者养成记\本地分析\tools')
import decode_resbin_extended as m
schemas, enums, readers = m.load_metadata()
native = m.Native()
key = ('ResDef', 'ResAttrLvImpactData')
va = schemas[key]['unpack_va']
original = b''.join(bytes(i.bytes) for i in native.instructions(va))
for mutation in ('truncate-buffer-pointer', 'clear-buffer-array'):
    raw = bytearray(original)
    if mutation == 'truncate-buffer-pointer':
        off = 0x1e8947c - va
        word = struct.unpack_from('<I', raw, off)[0]
        struct.pack_into('<I', raw, off, word & ~(1 << 31))
    else:
        struct.pack_into('<I', raw, 0x1e89498-va, 0xf9000a7f)
    altered = copy.copy(native)
    altered.instructions = lambda addr: (
        list(native.cs.disasm(bytes(raw), va))
        if addr == va else native.instructions(addr))
    analyzer = m.NativeAnalyzer(altered, schemas, enums, readers)
    try:
        analyzer.analyze(key)
    except m.EvidenceError as error:
        print(mutation, 'REJECTED:', error)
    else:
        print(mutation, 'ACCEPTED')
```

## 不是此次发现的缺陷

- 原生 readString 不显式验证终止字节；工具坚持终止 NUL 和严格 UTF-8，是已写明的保守子集，不据此判定原生等价或反向扩大接受范围。
- 对象已创建、非 null、受管数组边界有效、AAPCS64 被调用者保存、cutVer=1、reader 成功路径，均是模型明示前提。它们不是由解码器独立证明的运行时事实。
- 网络端序受初始化和 reader 原生行为支持，但运行时分支/虚调用未完成形式验证；FP 保留原始 int64，没有确认每字段单位/舍入/用途。
- 10 个载荷与候选 layout 最小大小不相容的条目保持拒绝，不应为了增加恢复数量跳过校验。
- 静态恢复客户端表，不等于获得服务端逻辑或当前在线生效配置。
