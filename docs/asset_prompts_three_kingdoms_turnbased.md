> 文档类型：AI 素材生产手册 / Asset Bible / Prompt Library<br>
> 文档版本：v1.0<br>
> 更新日期：2026-07-28<br>

> 目标用途：在新 Codex / Maker 会话中读取本文件，分批生成可进入游戏工程的角色 Sprite、动画帧、特效、场景、UI、图标和音频

## 0. 给后续素材生成会话的执行指令

后续新会话开始时，应先执行以下工作：

1. 完整读取本文件和对应游戏策划案。
2. 检查 `assets/` 下是否已有同 ID 素材，禁止无提示覆盖已确认版本。
3. 优先使用 Maker MCP 的素材工具：
   - 单图：`generate_image`
   - 同角色变体或动作：`edit_image`
   - 多个相互独立的图标：`batch_generate_images`
   - 音乐：`text_to_music`
   - 单个音效：`text_to_sound_effect`
   - 批量音效：`batch_sound_effects`
   - 角色对白：先 `audition_voices_for_character`，展示试听并等待用户选择；用户确认后才能 `confirm_character_voice` 和 `text_to_dialogue`
4. 每次只生产一个可验收批次，不要一次生成全部素材。
5. 角色必须先生成并确认“身份母版”，再以母版作为参考生成动作；不得对每个动作从纯文本重新抽卡式生成。
6. AI 原始结果存入 `_source`，通过验收、裁切、统一锚点和命名后才能进入 `runtime` 目录。
7. 每批完成后更新资产清单，记录提示词、模型/工具、日期、版本、参考图和人工修改说明。
8. 不生成任何竞品 Logo、影视演员脸、现有游戏角色服装、品牌纹样或受版权保护的独特视觉元素。
9. 所有图片默认不含文字；标题、数值和按钮文案由游戏 UI 字体渲染。
10. 若 Maker MCP 工具在新会话中不可见，先重启 Codex 或新开任务并检查 MCP，不要直接改变目录规则。

## 1. 素材生产目标与优先级

### 1.1 P0：战斗原型

优先做能构成 3 关战斗闭环的资源：

- 5 名武将：刘备、关羽、张飞、曹操、孙尚香。
- 4 类杂兵：西凉枪兵、盾卫、轻骑、弩手。
- 1 名 Boss：华雄。
- 3 张战斗背景：粮道、汜水关、华雄叫阵场。
- 通用受击、斩击、射击、治疗、护盾、破甲特效。
- 战斗 HUD、血条、战意条、状态图标、技能按钮。
- 1 首普通战斗 BGM、1 首 Boss BGM、基础战斗与 UI 音效。

### 1.2 P1：首章垂直切片

- 12 名首发武将的头像、卡面、战斗 Sprite。
- 8 类普通敌人。
- 胡轸、华雄、吕布三名 Boss。
- 第一章 6 套可复用战斗场景及昼夜/燃烧变体。
- 6 套装备、24 个装备图标。
- 角色技能图标、状态图标、阵营/职业/兵种图标。
- 主界面、征战、编队、武将、招募、装备、结算等核心 UI。
- 第一章地图、章节封面、4 张剧情插画。
- 4 首 BGM、约 45 个通用与技能音效。

### 1.3 P2：运营准备

- 其余武将完整动画、列传插画、动态招募演出。
- 精英词缀视觉、外观、活动 UI。
- 全武将语音。
- 宣传图、商店图、TapTap 详情页素材。
- 多档画质和首包/分包资源。

## 2. 总体美术圣经

### 2.1 核心风格

**原创国风水墨重彩、2D 横版战斗、3.5 头身英雄比例、清晰剪影、移动端高可读性。**

关键词：

- Chinese ink-and-color illustration
- stylized Three Kingdoms fantasy
- 3.5-head chibi heroic proportion
- clean silhouette
- hand-painted texture
- controlled brush edges
- readable mobile game sprite
- dramatic but not photorealistic

不采用：

- 写实照片脸。
- 1:1 真人比例战斗角色。
- 过度幼儿化的大头娃娃。
- 日式校服、现代枪械、科幻机甲。
- 厚重欧美油画、纯赛博朋克或纯卡通贴纸风。
- 任何具体商业游戏的画风名称。

### 2.2 阵营色板

| 阵营 | 主色 | 辅色 | 金属 | 特效倾向 |
|---|---|---|---|---|
| 魏 | `#223A5E` 深蓝 | `#4B5D77` 冷灰蓝 | 冷银 | 靛蓝军令、冷风、暗金 |
| 蜀 | `#2F6B4F` 竹青 | `#E8DFC6` 米白 | 暖青铜 | 青绿气劲、仁德金光 |
| 吴 | `#A33A2B` 朱红 | `#2C7180` 湖蓝 | 赤金 | 火焰、水纹、飞羽 |
| 群 | `#4B294F` 紫黑 | `#2B2B2F` 铁灰 | 暗金 | 紫月、黑红雷光 |
| 西凉军 | `#34383D` 黑铁 | `#7B2D2A` 暗红 | 粗铁 | 风沙、火星、黑烟 |

### 2.3 体型与轮廓

- 护卫：宽肩、低重心、大盾或厚甲，外轮廓接近梯形。
- 猛将：武器轮廓突出，披风或肩甲形成攻击方向。
- 骁骑：向前倾、长枪或长兵器，腿部和飘带具有速度感。
- 弓手：上身轻、手臂轮廓清晰，弓与箭袋不能和身体粘连。
- 谋士：长袖、羽扇、卷轴或令牌，轮廓避免过度厚重。
- 医辅：开放姿态、圆润衣摆、饰物少而精，避免武器喧宾夺主。

### 2.4 视觉可读性

- 角色缩放至 192 像素高时，仍能凭剪影认出职业与武器。
- 武器与身体至少留 8 像素视觉间隙。
- 面部细节不能成为识别角色的唯一依据。
- 普攻、战意技、受击和退场必须有完全不同的关键姿势。
- 特效中心不得持续遮挡血条和状态图标。

## 3. 技术规格

### 3.1 角色身份母版

| 类型 | 尺寸 | 格式 | 背景 | 用途 |
|---|---:|---|---|---|
| 全身正侧 3/4 母版 | 1024×1024 | PNG | 透明 | 动作生成参考 |
| 三视图设定 | 2048×1024 | PNG | 浅灰或透明 | 正面、3/4、背面一致性 |
| 半身卡面 | 1024×1280 | PNG | 透明 | 招募、图鉴、技能切入 |
| 方形头像 | 512×512 | PNG | 透明 | HUD、列表 |
| 剪影检查图 | 256×256 | PNG | 纯白 | 可读性 QA |

### 3.2 战斗动画帧

- 单帧工作尺寸：512×512 RGBA PNG。
- 最终显示高度：普通武将约 220～280 像素；Boss 约 320～420 像素。
- 角色脚底锚点：`x=256, y=448`。
- 角色默认朝右；敌方在引擎中水平翻转。具有文字、单侧徽记或方向敏感武器时，需单独制作左向版本。
- 透明边缘保留至少 8 像素空白。
- 不带地面阴影；地面影子作为独立通用 Sprite。
- 每一动作的画布、锚点、比例和相机角度必须完全一致。

### 3.3 动作规格

| 动作 ID | 帧数 | FPS | 循环 | 必需 | 说明 |
|---|---:|---:|---|---|---|
| idle | 6 | 8 | 是 | 是 | 呼吸、布料和武器轻微运动 |
| attack_a | 8 | 12 | 否 | 是 | 普攻，命中帧建议第 5 帧 |
| skill | 12 | 12 | 否 | 是 | 战意技主体动作，不含屏幕特效 |
| hit | 4 | 12 | 否 | 是 | 受击后退但脚点不漂移 |
| ko | 8 | 10 | 否 | 是 | 失去战斗能力，不表现血腥 |
| victory | 6 | 8 | 是 | 是 | 胜利短循环 |
| enter | 8 | 12 | 否 | 可选 | 入场或突进 |
| run | 8 | 12 | 是 | 可选 | 赵云、吕布、轻骑等 |

说明：

- `ko` 统一表示退场，避免 `death` 在文件名和内容审核中产生不必要歧义。
- 生成阶段优先得到动作关键帧，再由人工补间或图像编辑扩展帧数。
- 不建议要求图像模型一次生成包含全部动作的大型 Sprite Sheet，容易出现服装、武器和比例漂移。

### 3.4 背景

- 基准：1920×1080，横屏 16:9。
- 降级：1280×720。
- 推荐拆分 3 层：
  - `far`：天空、远山、城墙。
  - `mid`：营帐、旗帜、树木、建筑。
  - `near`：地面、前景草、烟尘。
- 战斗可用区域中央必须保持干净，禁止大面积高对比物体干扰角色。
- 不包含人物、文字、Logo、UI 和不可交互的假按钮。

### 3.5 UI 与图标

- 图标母版：512×512，最终导出 256×256 和 128×128。
- 技能/物品图标保持 12%安全边距。
- 面板和按钮优先生成无文字底板。
- 九宫格拉伸组件需明确不可拉伸边框区域。
- 所有 UI 资源需要普通、按下、禁用、选中四态时，尽量通过颜色或 shader 派生，减少重复图片。

### 3.6 音频

- BGM：44.1 kHz 或 48 kHz，立体声，循环点自然。
- SFX：44.1 kHz，短音效可单声道。
- 对白：48 kHz，单声道，干声，无混响或背景音乐。
- 保留工具实际生成的扩展名，不可只改后缀伪装格式。
- Maker MCP 不负责把生成音频转成 OGG；需要转换时另行建立受控转换流程。

## 5. 文件命名规则

### 5.1 通用规则

- 只使用 ASCII 小写字母、数字和下划线。
- 不使用空格、中文、括号、`@`、`#`。
- ID 一经进入配置表不可随意修改。
- 版本号用三位数字：`v001`、`v002`。
- 动画帧序号从 `00` 开始。

### 5.2 命名模板

| 类型 | 模板 | 示例 |
|---|---|---|
| 角色母版 | `src_<id>_master_v###.png` | `src_hero_liu_bei_master_v001.png` |
| 角色三视图 | `src_<id>_turnaround_v###.png` | `src_hero_guan_yu_turnaround_v001.png` |
| 动画帧 | `spr_<id>_<action>_<dir>_<frame>.png` | `spr_hero_zhang_fei_attack_a_r_05.png` |
| 半身卡面 | `prt_<id>_<variant>_v###.png` | `prt_hero_cao_cao_default_v001.png` |
| 头像 | `ava_<id>_<variant>_v###.png` | `ava_hero_diao_chan_default_v001.png` |
| 特效帧 | `vfx_<id>_<phase>_<frame>.png` | `vfx_slash_cyan_impact_03.png` |
| 背景层 | `bg_<scene_id>_<layer>_v###.png` | `bg_hulao_gate_far_v001.png` |
| UI | `ui_<screen>_<element>_<state>.png` | `ui_battle_skill_button_ready.png` |
| 图标 | `ico_<category>_<id>_v###.png` | `ico_status_stun_v001.png` |
| BGM | `bgm_<scene_or_mode>_v###.<ext>` | `bgm_hulao_boss_v001.wav` |
| 音效 | `sfx_<category>_<id>_<variant>.<ext>` | `sfx_weapon_spear_hit_01.wav` |
| 对白 | `vo_<hero_id>_<event>_<index>.<ext>` | `vo_hero_liu_bei_skill_01.wav` |

方向：

- `r`：朝右，标准源。
- `l`：朝左，仅方向敏感时制作。

### 5.3 禁止命名

- `最终版.png`
- `新建文件夹/1.png`
- `guanyu2_new_final_final.png`
- `刘备待机.png`
- 仅以日期命名而没有资产 ID。

## 6. 通用图像提示词

### 6.1 通用正向块

将以下内容作为所有角色类提示词的固定前缀：

```text
原创汉末幻想题材的2D横版手机游戏角色素材，国风水墨重彩手绘，
3.5头身英雄比例，清晰有力的外轮廓，移动端缩小后仍可识别，
服装和甲胄参考汉代轮廓但进行原创幻想化设计，材质区分明确，
正侧面三分之二视角，全身完整，角色默认面向画面右侧，
固定正交相机，固定比例，固定脚底锚点，柔和顶侧光，
透明背景，边缘干净，无地面，无阴影，无文字，无边框。
```

### 6.2 通用负向块

```text
不要写实照片，不要影视演员脸，不要模仿任何现有游戏角色，
不要现代服装，不要科幻机械，不要枪械，不要日本武士甲，
不要多余肢体、重复武器、畸形手指、漂浮饰品、断裂兵器，
不要改变角色年龄、脸型、发型、服装、主色、武器长度，
不要透视变化，不要相机旋转，不要裁切头顶或脚底，
不要复杂背景，不要地面投影，不要血腥、断肢、伤口，
不要文字、Logo、水印、签名、UI、边框。
```

### 6.3 身份一致性强制语句

在通过 `edit_image` 生成动作时追加：

```text
严格保持参考图中的身份一致性：同一张脸、年龄、发型、头冠、
服装结构、甲片数量、纹样位置、武器造型和配色；只改变姿势、
表情与受物理影响的布料，不得重新设计角色。
```

## 8. 角色动作生成模板

使用方式：

```text
角色身份母版提示词
+ 身份一致性强制语句
+ 对应动作提示词
+ 通用负向块
```

生成顺序：关键帧 → 动作条 → 单帧切分 → 锚点统一 → 边缘清理 → 动画预览。

### 8.1 `idle`

```text
生成6帧横版待机循环的关键姿势序列。角色双脚位置与脚底锚点绝对固定，
胸肩有轻微呼吸起伏，发梢、衣摆、披风和武器挂饰产生极小幅度延迟摆动。
第一帧与第六帧可以无缝连接；动作克制，不左右走动，不改变武器握持方式。
每帧独立透明背景，角色大小和相机完全一致。
```

### 8.2 `attack_a`

近战：

```text
生成8帧横版近战普通攻击：预备2帧、向前踏步2帧、武器命中关键帧1帧、
随势2帧、回到原位1帧。攻击方向朝右，命中点位于角色前方约一个身位。
不生成刀光特效，特效作为独立资源；脚底最终回到固定锚点。
```

弓手：

```text
生成8帧横版弓箭普通攻击：取箭、搭箭、拉弓、满弦、释放、弓弦回弹、
收势、恢复待机。箭在释放帧后离开画面，另做投射物资源。
保持弓结构、箭袋数量和角色身份一致。
```

谋士/医辅：

```text
生成8帧横版施术普攻：抬手或挥扇、聚气、向右推出、释放、
袖摆跟随、收势并恢复。只保留手部轻微光点，不生成大范围最终特效。
```

### 8.3 `skill`

```text
生成12帧战意技主体动作：蓄势3帧、标志性姿势2帧、主要攻击或施术4帧、
收束2帧、恢复1帧。动作幅度明显高于普攻，角色可以短暂离开原锚点，
但最后必须回到原位置。不得把技能特效画死在角色身体上，
只保留武器接触点或手部发光，完整特效独立生成。
```

### 8.4 `hit`

```text
生成4帧非血腥受击动作：身体向左后方受力、武器或手臂抬起防护、
最大后仰、迅速恢复。脚底位移不超过画布宽度的3%，不改变服装和武器，
不出现伤口、血液、断裂或倒地。
```

### 8.5 `ko`

```text
生成8帧失去战斗能力的退场动作：受力、单膝跪地、武器触地、
身体保持可识别的非血腥失败姿势，最后轻微淡出由引擎完成。
不出现尸体、血液、断肢、武器刺入身体或夸张痛苦表情。
```

### 8.6 `victory`

```text
生成6帧短胜利循环。角色做符合身份的克制庆祝动作：
统帅收剑颔首，猛将举兵器，谋士收扇，弓手旋弓后站定，辅助拱手。
动作可循环，不跳跃出画布，不加入文字和背景。
```

- 招募竹简展开。
- 战斗胜利 / 失败。
- 三星依次点亮。

UI 音效单个控制在 0.1～1.2 秒，连续点击音效需避免刺耳高频。

## 19. 角色语音生产规范

### 19.1 必备语音事件

每名 P1 武将建议：

- `obtain_01`：获得武将。
- `deploy_01`：上阵。
- `battle_start_01`：开战。
- `attack_01/02`：普攻短促气声。
- `skill_01`：战意技。
- `hit_01/02`：受击。
- `victory_01`：胜利。
- `low_hp_01`：低生命。
- `bond_01`：图鉴或好感。

### 19.2 声线要求

- 不模仿影视演员、配音演员或现有游戏声线。
- 先通过 `audition_voices_for_character` 生成试听。
- 必须展示试听给用户并等待明确选择。
- 未经用户选择，不得自行确认角色声线。

### 19.3 台词原则

- 每句 4～16 个汉字为主。
- 战斗中避免超过 2.5 秒。
- 不滥用网络流行梗。
- 不让同一历史人物直接复述其他作品的著名台词。
- 可以使用通用历史意象，但句式必须原创。

示例原创台词：

| 武将 | 事件 | 台词 |
|---|---|---|
| 刘备 | skill | “同袍并肩，守住此阵！” |
| 关羽 | skill | “刀落之处，阵势皆开。” |
| 张飞 | skill | “都给我站稳了！” |
| 曹操 | skill | “先夺其势，再破其军。” |
| 孙尚香 | skill | “这一箭，穿阵！” |
| 吕布 | skill | “谁敢挡我？” |

## 23. 图像处理与集成检查

### 23.1 单帧检查

- 透明背景真实存在，不是灰白棋盘格画进图片。
- 无水印、签名和随机文字。
- 没有多余手指、重复武器、断裂饰物。
- 与母版的脸、发型、头冠、服装和武器一致。
- 脚底未裁切，武器未触碰画布边缘。
- 色彩位于阵营色板范围内。

### 23.2 动画检查

- 所有帧画布一致。
- 脚底锚点一致。
- 身高波动不超过 3%，除非动作明确蹲下或跃起。
- 武器长度波动不超过 5%。
- 第一帧与最后一帧能平滑过渡。
- 命中帧和代码事件点已记录。
- 水平翻转后武器和服装没有明显逻辑错误。
- 192 像素显示高度下仍可读。

### 23.3 背景检查

- 中央战斗区不抢视觉。
- 我方、敌方和 Boss 站位均不与高对比背景重叠。
- 16:9、19.5:9 安全裁切不丢失关键信息。
- 三层视差边缘可拼接，没有透明缝。
- 没有现代物件、文字、Logo和人物。

### 23.4 UI 检查

- 48×48 CSS 像素触控目标。
- 32×32 下状态图标可辨。
- 不仅用颜色表达状态。
- 九宫格组件拉伸后边框不变形。
- 文案全部由字体渲染。
- 安全区避让宿主胶囊和圆角。

### 23.5 音频检查

- 无爆音、底噪、截断。
- 循环点没有明显咔哒声。
- 普攻连续播放不刺耳。
- Boss 音效不会完全盖过技能提示。
- 对白没有背景音乐和房间混响。
- 记录生成来源和使用许可。

## 25. 最终交付标准

一个资产只有同时满足以下条件，才可标记为 `integrated`：

- ID 与策划配置一致。
- 路径和文件名符合本规范。
- 已保存原始生成记录和提示词。
- 已通过视觉、透明通道、锚点、尺寸与性能检查。
- 角色与身份母版一致。
- 动画已在引擎实际播放，不仅查看静帧。
- 背景已在目标横屏比例和安全区测试。
- 音频已在手机扬声器和耳机各试听一次。
- 不含未经授权的 Logo、演员脸、竞品设计或第三方素材。
- 已由用户或指定美术验收，并记录确认版本。
